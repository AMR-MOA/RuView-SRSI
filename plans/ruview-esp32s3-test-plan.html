Phase 0 — Concepts

Read once. This is the vocabulary the rest of the plan uses. No commands.

0.1 What CSI actually is

Your WiFi radio does not receive one signal. An 802.11n 20 MHz channel is split into 56 subcarriers — narrow frequency slots transmitted in parallel. To decode a packet the receiver must estimate, for each subcarrier, how the channel distorted it. That estimate is a complex number: an amplitude (attenuation) and a phase (delay).

That per-subcarrier complex vector is Channel State Information. Every WiFi chip computes it. Almost none let you read it. The ESP32 does.

transmitted received ┌─────────────────┐ ┌─────────────────┐ │ ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁ │ ──────► │ ▁▃▅▂▇▁▄▆▂▁▅▃▁▂▄ │ 56 subcarriers └─────────────────┘ the room └─────────────────┘ changes it

Why a human shows up in it. Radio waves reflect off you — your body is mostly water, a strong reflector at 2.4 GHz. The received signal is the sum of the direct path plus every reflection. Move, or just breathe, and reflected path lengths change by millimetres, which changes the phase of that sum. Chest-wall motion during breathing is 4–12 mm; the wavelength at 2.4 GHz is 125 mm. A 12 mm path change is ~35° of phase — enormous next to the noise floor.

The key idea This is why it works through walls and in the dark. The system is not seeing you. It is measuring how you perturb a radio field that already fills the room.

0.3 What is real vs. what is a demo

This repo is unusually honest about this, and you should hold it to that standard.

Solid — expect these to work Raw CSI streaming at ~20 Hz · breathing rate (0.1–0.5 Hz → 6–30 BPM) on a still subject · motion / activity · the ADR-151 calibration → enrollment → specialist-bank pipeline · multistatic fusion of several nodes.
Weaker — expect noise Heart rate (0.8–2.0 Hz) — much lower SNR; needs a still, close subject.
Presence — the firmware's is a variance threshold, not a model; false-positives on fans, microwaves, AP power swings.
Person counting — the firmware's n_persons is a slot-capacity heuristic over top-K subcarrier groups (main/edge_processing.c:481). It tracks subcarrier diversity, not people. TROUBLESHOOTING §2 documents it reading 6–8 for 5 bodies.
Not real yet — don't spend time here 17-keypoint pose from CSI alone. The committed on-device model scores PCK@20 = 3.0% against a ≥35% target, and its runtime path is a confidence=0 stub. Without --model, the on-screen skeleton is driven by amplitude-variance heuristics. The 82.69% MM-Fi figure is a separate published benchmark on a research dataset, not this path.

Loading the Hugging Face weights. The HF bundle is JSONL RVF; --model only parses binary RVF. It errors on magic mismatch and degrades to null output. Run without --model.

0.4 Your specific hardware

Read from the chips' eFuses, not guessed from a datasheet:

Chip           ESP32-S3 (QFN56) rev v0.1
Flash          8 MB, in-package, GigaDevice
PSRAM          None    (PSRAM_CAP = None, PSRAM_CAPACITY = 0)
USB            USB-Serial/JTAG, native      (VID 303A / PID 1001)
MACs seen      f4:12:fa:9d:b6:a4 (COM3)
               f4:12:fa:9d:b6:d4 (COM4)

Three consequences, all of which will bite you if ignored:

  1. No PSRAM → Tier 3 WASM is out, and the AMOLED display code has no framebuffer memory. You will compile both out.
  2. Native USB only → the default ESP-IDF console goes to UART0, which is not wired to this USB port. Without a config change your serial monitor is silent, and you will misdiagnose a working board as dead.
  3. Display probe false-positive → the SH8601 panel driver is write-only, so its init "succeeds" on a board with no panel. When the firmware thinks it has a display it keeps the promiscuous filter at MGMT-only, and CSI yield collapses to 0 pps while the node still associates, still pings, and looks perfectly healthy. This is the nastiest failure mode in the project. You will compile display support out to make it impossible.

⚠ Read this before using Docker with more than one node Docker Desktop on Windows runs the engine inside a WSL2/Hyper-V VM. Inbound UDP from multiple source IPs is demultiplexed onto a single virtual socket — the first source IP wins and every other node is silently dropped. With 6 nodes you would see 1. --network host does not help (not implemented for the Linux engine on Windows).

Full detail: docs/TROUBLESHOOTING.md §9. Running sensing-server natively avoids this entirely — which is why this plan builds it natively.

Phase 6 — Vitals

PS> & $py firmware\esp32-csi-node\provision.py --port COM3 --edge-tier 2

Only the changed key is written; SSID and target survive. Power-cycle the node.

What Tier 2 adds on-device

  • Breathing: biquad IIR bandpass 0.1–0.5 Hz, zero-crossing → 6–30 BPM
  • Heart rate: bandpass 0.8–2.0 Hz → 40–120 BPM
  • Presence: phase variance vs an adaptively calibrated threshold (60 s ambient learning at boot)
  • Fall: phase acceleration over threshold
  • A 32-byte vitals packet (0xC5110002) at 1 Hz
⚠ The 60-second ambient calibration happens at boot Power-cycle the node with the room empty, and stay out for the first minute. Calibrate with a person present and the threshold is poisoned for the whole session.

Setup that actually works

Breathing is a millimetre-scale chest motion, so geometry matters more than anything else:

  • Node 1.0–1.5 m from your chest
  • Node at chest height when you are seated
  • Chest facing the node (chest-centric geometry, per Step 2.4)
  • Sit still. Any gross motion swamps the breathing band completely.
  • Quiet RF: no microwave running, no fan directly in the path
PS> curl.exe http://localhost:3000/api/v1/vital-signs   # host-computed
PS> curl.exe http://localhost:3000/api/v1/edge-vitals   # node-computed (Tier 2)

Comparing the two is a genuinely useful cross-check.

Protocol — 3 × 2-minute runs

RunYou doExpect
ABreathe normally, still12–18 BPM
BBreathe deliberately slowly, ~6 s/cycle~10 BPM
CBreathe fast, ~2 s/cycle~30 BPM

Count your actual breaths with a stopwatch. That is your ground truth.

✅ PassReported BPM tracks the direction of A → B → C and lands within ±3 BPM of your count in at least 2 of 3 runs.
❌ Fail — flat or nonsenseAlmost always geometry. Move closer, get to chest height, hold still. Also confirm the node is still streaming — a silent node reports stale vitals rather than erroring.

Heart rate is a much weaker signal than breathing: smaller displacement, higher frequency, and it sits inside breathing harmonics. Set expectations low.

Setup: everything from 6.2, plus node within ~1 m, and hold your breath for 15–20 s bursts to remove the dominant interferer. Compare against a pulse oximeter, fitness watch, or manual radial-pulse count.

✅ PassWithin ±10 BPM during breath-hold, on at least some runs.
❌ FailThis is a known-weak capability. Record what you saw and move on — do not sink hours here.

⚠ SafetyUse a mattress or thick cushion. Do not actually fall.

Fall detection is a phase-acceleration threshold with a 3-frame debounce and a 5 s cooldown. Default: 2.0 rad/s² (fall_thresh=2000).

From standing, drop rapidly onto a mattress in view of the node. Watch /api/v1/edge-vitals for the fall flag (bit 1 of the flags byte). Tune without reflashing:

PS> & $py firmware\esp32-csi-node\provision.py --port COM3 --fall-thresh 1500

(Lower = more sensitive = more false positives.)

✅ PassFlag fires on 3 of 5 deliberate drops, without firing during normal walking.

Physics, so you know what to expect

One-way attenuation at 2.4 GHz, approximately:

MaterialLoss
Drywall / plasterboard3–5 dB
Wooden door3–6 dB
Brick8–15 dB
Concrete15–25 dB
Reinforced concrete / metal mesh25 dB+ — effectively opaque

The repo claims through-wall to ~5 m, signal-dependent. Drywall works well. Reinforced concrete does not. Start with the easiest wall you have.

  1. Put 2–3 nodes on one side of an interior drywall wall.
  2. Record an empty-room baseline with nobody on either side: 
    PS> .\target\release\wifi-densepose.exe calibrate --duration-s 60 `
      --output ..\ruview-data\baseline-throughwall.bin
  3. Have someone walk on the far side while you watch amplitude variance and presence.
  4. Alternate 60 s present / 60 s absent, five cycles, logging each.
✅ PassPresence tracks the far-side person on ≥ 3 of 5 cycles.
❌ FailThicker wall than expected, or too far. Move nodes closer to the wall, try a doorway (huge difference), and confirm same-side detection still works so you know the nodes are healthy.
⚠ Guard against fooling yourselfThrough-wall demos are easy to fake accidentally — footsteps vibrating the floor, a door moving, the person's phone associating with the AP. Run a negative control: the same five cycles with the far-side person replaced by nothing at all. If your detector fires anyway, you are measuring something other than the person.
